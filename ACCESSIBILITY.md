# Accessibility Statement for `reed-solomon-alg-mcp`

The maintainers of `reed-solomon-alg-mcp` are committed to ensuring digital accessibility for all users, including developers and users who rely on assistive technologies or specialized terminal interfaces.

---

## 1. Scope & Architecture

`reed-solomon-alg-mcp` is a Model Context Protocol (MCP) server written in Rust that operates primarily over `stdio` (Standard Input / Standard Output) transport, both natively and via Docker containerization.

Because this application functions as a background protocol worker rather than a graphical user interface (GUI), primary accessibility considerations focus on:
* **Protocol & Output Compatibility:** Outputting clean, unformatted JSON-RPC over `stdio` without embedded ANSI color/escape sequences that corrupt screen reader parsing or client log interpreters.
* **CLI Interoperability:** Ensuring local configuration tools and manual execution paths operate seamlessly with command-line screen readers (e.g., NVDA with terminal access, Orca, VoiceOver terminal integration).
* **Documentation Accessibility:** Providing standard, high-contrast, screen-reader-friendly Markdown documentation across repository materials and published package registries.

---

## 2. Standards Compliance

We strive to align our documentation, metadata, and CLI diagnostics with the core principles of the **Web Content Accessibility Guidelines (WCAG) 2.1 Level AA** where applicable:

| Principle | Implementation in `reed-solomon-alg-mcp` |
| :--- | :--- |
| **Perceivable** | All Markdown files include explicit `alt` text for diagrams, icons, and status badges. Text content uses semantic headers (`#`, `##`, `###`) for screen reader navigation. |
| **Operable** | Complete CLI execution and testing can be performed entirely using a keyboard across Linux, macOS, and Windows terminals. |
| **Understandable** | Structured error codes, standard MCP JSON-RPC payload structures, and clear error output without jargon. |
| **Robust** | Sticking to standard MCP specifications and POSIX-compliant standard I/O streams (`stdin`, `stdout`, `stderr`). |

---

## 3. Terminal & CLI Accessibility Guidelines

When running or developing for `reed-solomon-alg-mcp`, the following standards are observed:

* **Separation of Streams:** Protocol payloads are strictly output to `stdout`. All diagnostic logs, warnings, or debug messages are routed to `stderr` to ensure protocol parsing and screen reader reading streams remain unpolluted.
* **Color Neutrality:** Terminal output generated by default does not enforce color contrast combinations that impede low-vision users.
* **Standard Unicode:** Avoidance of decorative ASCII art or complex Unicode box-drawing characters in logs that can produce verbose or disruptive text-to-speech output.

---

## 4. Known Issues & Limitations

* **Screen Readers with Docker Logs:** When wrapping execution in `docker run -i`, some terminal screen readers may read container initialization strings. Running the native binary (`target/release/reed-solomon-alg-mcp`) directly provides a cleaner screen-reader experience.

---

## 5. Feedback & Reporting Issues

We welcome feedback on how to improve the accessibility of this project. If you encounter any barriers or have suggestions:

1. **GitHub Issues:** Open an issue on GitHub with the label `accessibility`.
2. **Details to Include:** Please describe the assistive technology used (e.g., screen reader, specialized terminal emulator), the command or document affected, and the expected behavior.
